# 키움 자동매매

Windows EXE로 빌드 가능한 주식 자동매매 MVP입니다.

현재 배포판의 내부 기준은 `v37`이며, 실행 창 제목과 좌측 상단에는 `키움 자동매매`만 표시됩니다. 화면에
`현재 버전은 REST API 실거래 주문이 잠겨 있습니다`라는 경고가 나오거나 자동주문
버튼이 `상승 설정`/`하락 설정`으로 표시되면 v28 이하 구버전 EXE를 실행한 것입니다.
최신 파일의 `자동매도 설정`/`자동매수 설정` 버튼을 사용해야 실거래 세션 승인과
키움 공식 정규장 신호를 거치는 현재 주문 경로가 적용됩니다.

REST API 실전투자 AppKey/SecretKey로 연결하면 모의투자 연결이나 모의투자 선행
실행 없이 자동주문 조건을 설정할 수 있습니다. `자동매도 설정` 또는 `자동매수 설정`
확인창에서 승인하면 현재 실행의 `실거래 자동주문 승인`도 함께 켜집니다. 장 시작
전에는 `장 시작 대기` 상태로 조건을 보존합니다. 공식 장시작시간 `0s`의 장운영구분
`3` 또는 최근 주식체결 `0B`의 장구분 `290=2`가 확인되기 전에는 실제 주문을
보내지 않습니다.

기본 주문 실행은 모의 모드입니다. 실계좌 매수/매도 주문은 잠금이 기본 적용되어
있으며, 키움 OpenAPI+ 또는 키움 REST API 모의투자 연결 후 조회와 시장가 주문
요청을 테스트할 수 있습니다. REST 실전투자는 연결만으로 주문이 열리지 않습니다.
계좌·종목·수량·고정 운용금액 확인, 실행 세션의 명시적 실거래 승인, 키움의 공식
정규장 장중 신호가 모두 확인된 경우에만 실제 주문 경로가 활성화됩니다.

## 포함 기능

- 한글 Tkinter 데스크톱 대시보드
- 키움 OpenAPI+ 공식 로그인 및 계좌·잔고 확인 흐름
- 키움 REST API 실전투자/모의투자 환경 선택 및 AppKey/SecretKey 토큰 연결
- 다운로드 폴더의 AppKey·SecretKey 파일 자동 찾기와 개별 파일 선택
- REST 접근토큰 `au10001` 및 계좌번호 `ka00001` 검증
- 로그인 오류코드 안내 및 모의투자/실거래 서버 구분 표시
- 로그인 후 API 10자리 계좌의 기본 8자리를 읽기 전용 `4자리 - 4자리` 칸에 자동 표시
- 계좌 로딩 후 활성화되는 마스킹 비밀번호 입력칸과 세션 기반 `비밀번호 세팅` 주문 잠금
- 키움 현재가 조회 `opt10001` / `ka10001`
- 관심종목 최대 20개 저장 및 공식 REST 관심종목정보 `ka10095` 일괄 조회
- 키움 1·3·5·10·15·30·45·60분봉 조회 `opt10080` / `ka10080`
- REST 1틱 차트 `ka10079`를 실제 체결시간 기준 1·5·10초봉으로 집계
- 키움 계좌 잔고 조회 `opw00018`
- 키움 예수금·주문가능·출금가능금액 조회 `opw00001` / `kt00001`
- 키움 실시간 시세 등록 `SetRealReg`
- REST WebSocket 로그인 및 주식체결 실시간 등록 `0B`
- REST WebSocket 등록 완료·다음 체결 대기·첫 실시간 체결 상태 표시와 로그
- REST/OpenAPI+ 장시작시간 `0s` 및 REST 주식체결 `0B` 장구분 `290=2` 정규장 확인
- 실시간 체결량을 실제 1·5·10초 OHLC 봉으로 집계
- 초기 종목번호 `000000` 및 `종목 세팅` 버튼을 통한 회사명 명시 조회
- 키움 공식 일봉 `ka10081`/`opt10081`로 Wilder DMI 1~99일 버튼형 계산
- `+DI` 우세 강세·`-DI` 우세 약세 전환 기반 자동 판단 버튼
- 전략 판단 결과를 모의투자 서버용 시장가 주문 `SendOrder`에 연결
- REST 모의투자 시장가 매수 `kt10000` / 매도 `kt10001`
- REST 실전 시장가 매수 `kt10000` / 매도 `kt10001` 세션 승인 경로
- 별도 구획의 기본 `0주` 및 `-`/`+` 버튼형 주문수량 선택기
- 선택한 주문수량을 수동·전략 매수/매도의 공식 `ord_qty`에 그대로 적용
- 종목별 고정 운용금액·기준가·설정일 SQLite 저장 및 명시적 리세팅
- 일봉 DMI 강세와 `+% 상승`을 함께 만족할 때 자동매수
- 일봉 DMI 약세와 `-% 하락`을 함께 만족할 때 자동매도
- 조건 도달 시 주문을 한 번만 요청하고 해당 퍼센트 설정을 자동 해제
- 모의투자 매도 요청의 명시적 실패 시 최대 3회 재시도(매수·실거래 재시도 금지)
- 회사명과 계좌가 확인된 뒤 활성화되는 수동 매수/매도 버튼
- 자동운용 시작 시각 표시와 시작·중지 후 최근 시작 시각 유지
- 장 운영 시간과 별도로 계좌·종목·수량·금액·승인·자동조건을 확인하는 자동매매 ON/OFF 배지
- 매수·매도 종목명, 수량, 요청시세, 예상총액, 주문번호와 결과를 보여주는 전용 이력 탭
- 사용자 문서 폴더에 UTF-8 CSV 매수·매도 이력 영구 기록
- 기본 실거래 잠금, 실행 세션 승인, 장중 확인 및 수동 주문 최종 확인창
- OpenAPI+ TR 제한(초당 5건, 분당 100건, 시간당 1,000건) 자동 대기
- REST 국내주식 초당 5건 및 모의투자 동일 API ID 초당 1건 제한 자동 대기
- DMI 약세→강세 매수, 강세→약세 매도 전략 엔진과 동일 봉 중복 방지
- 영웅문형 주기 선택·지표 설정·우측 가격축·십자선 툴팁이 있는 멀티주기 차트
- MA5·MA20, 분홍 강세·파랑 약세 배경, +DI/-DI/ADX 및 매수·매도 표식
- 종목별 운용 한도 위험관리
- 수동 매수 수량의 운용 한도 및 조회된 보유 수량 초과 매도 사전 차단
- 모의 브로커, 주문 관리자, 매도 재시도 흐름
- SQLite 주문/로그 저장
- 단위 테스트
- Windows EXE 빌드 스크립트
- GitHub Actions Windows EXE 빌드 워크플로

## 자동운용 상태와 매수·매도 이력

`자동 운용 시작`을 누르면 버튼 아래에 시작 날짜와 시각을 초 단위로 표시하고 시스템
로그에도 같은 시각을 기록합니다. 운용을 중지한 뒤에도 마지막 시작 시각을 유지하여
언제 실행을 시작했는지 확인할 수 있습니다.

시작 버튼 옆의 `자동매매 가능 ON`/`자동매매 OFF` 배지는 계좌 연결, 종목 세팅,
1주 이상 주문 수량, 고정 운용금액, 실거래 세션 승인, DMI 또는 퍼센트 자동주문 조건을
종합합니다. 이 표시는 장이 닫혀 있을 때도 다음 장에서 주문할 준비가 끝났는지 확인할
수 있도록 장 운영 시간과 독립적으로 계산합니다. 녹색 ON이어도 실제 실거래 주문은
기존 안전장치대로 키움 공식 정규장 장중 신호가 확인된 뒤에만 전송됩니다.

`계좌·주문·로그` 옆의 `매수·매도 이력` 탭에는 각 주문 요청의 시각, 매수/매도,
종목번호·종목명, 수량, 요청 당시 시세, 예상총액, 접수/실패, 주문번호, 거래환경과
메시지를 표시합니다. REST 주문번호는 키움 `kt10000`/`kt10001` 응답의 `ord_no`를
사용합니다. 시장가 주문의 요청시세와 예상총액은 주문 직전 화면 시세를 기준으로 한
참고값이며 실제 체결가와 체결금액은 다를 수 있습니다.

같은 내용은 프로그램을 다시 실행해도 남도록 다음 CSV 파일에 추가 기록됩니다.

`%USERPROFILE%\Documents\KiwoomAutoTrader\매수매도_이력.csv`

이력 탭의 `CSV 로그 열기` 버튼으로 파일을 바로 열 수 있습니다. 계좌 비밀번호,
AppKey, SecretKey와 접근토큰은 이력 화면·SQLite·CSV 어디에도 기록하지 않습니다.

## 키움 계좌 연결

상단 `OpenAPI+ 로그인` 버튼은 키움 OpenAPI+ ActiveX의 `CommConnect()`로 로그인 창을
띄운 뒤 `GetLoginInfo("ACCNO")`로 계좌 목록을 조회합니다.
화면에는 키움 API 10자리 계좌번호에서 상품코드 2자리를 제외한 기본 8자리를
`앞 4자리-다음 4자리`로 표시하고, 내부 조회와 주문 요청에는 키움에서 받은 원본
10자리 계좌번호를 사용합니다.

공식 페이지:

- https://www1.kiwoom.com/h/main
- https://www.kiwoom.com/h/customer/download/VOpenApiInfoView
- https://download.kiwoom.com/web/openapi/OpenAPISetup.exe

로그인 창의 `키움 홈페이지 열기` 버튼은 위 공식 홈페이지를 엽니다. 홈페이지의
로그인 상태와 OpenAPI+ ActiveX 로그인 상태는 별도이므로, 홈페이지에 로그인한
뒤에도 앱의 `로그인` 버튼을 눌러 OpenAPI+ 공식 로그인 절차를 완료해야 합니다.
앱의 연결 표시는 `GetConnectState()`가 연결을 확인한 경우에만 `ON 연결됨`으로
바뀝니다.

앱 로그인 창에는 확인할 키움 ID만 입력합니다. 비밀번호와 인증서는 앱이 받거나
저장하지 않고 키움 OpenAPI+ 공식 로그인 창에서 직접 입력합니다. 로그인 완료 후
`GetLoginInfo("USER_ID")`가 앱에 입력한 ID와 일치해야 계좌와 주문 기능이
활성화됩니다. 연결 중에는 `GetConnectState()`를 주기적으로 다시 확인하며 연결이
끊기면 자동운용, 실시간 시세 상태, 잔고와 주문 기능을 즉시 차단합니다.

로그인 직후에는 키움이 반환한 `ACCOUNT_CNT`와 `ACCNO` 계좌 목록 개수까지
대조합니다. ID와 계좌 정보 수신이 모두 검증된 경우에만 첫 계좌를 자동 선택하고,
입력된 종목의 종목명·현재가 조회와 실시간 시세 등록 및 계좌 잔고 조회를
시작합니다. 계좌정보 창에서 로그인 이벤트, 정보 수신, 서버 구분과 마스킹된
선택 계좌를 확인할 수 있습니다.

OpenAPI+ 예수금·잔고 조회의 계좌 비밀번호는 숫자 4~8자리만 입력할 수 있습니다.
메인 화면의 계좌번호가 키움에서 로딩된 뒤에만 마스킹 입력칸과 `비밀번호 세팅`
버튼이 활성화됩니다. 버튼을 누르면 `opw00001` 예수금과 `opw00018` 평가잔고를
실제 조회하며, 성공한 경우에만 `확인됨`과 초록색 `ON 연결됨`을 표시하고
매수·매도·전략 주문 버튼을 활성화합니다. 확인 전이나 실패 시에는 주문 버튼이
잠깁니다.

확인된 비밀번호는 현재 프로그램 실행 세션의 메모리에만 유지됩니다. 수동 주문,
일봉 DMI 자동주문과 DMI·등락률 결합 일회성 자동주문은 실제 `SendOrder()` 호출
직전에 같은 비밀번호로 `opw00001`/`opw00018`을 다시 조회하여 계좌 접근과 최신
주문가능금액·보유수량을 확인합니다. 비밀번호가 바뀌거나 재확인에 실패하면 즉시
세션 값을 지우고 주문 기능을 다시 잠급니다.

REST API는 계좌 비밀번호를 사용하지 않으므로 토큰과 계좌 조회가 성공하면 바로
`ON 연결됨`으로 표시됩니다.
입력한 비밀번호는 설정, SQLite, 파일 또는 로그에 저장하지 않으며 프로그램 종료,
OpenAPI+ 연결 해제, 계좌 변경 시 입력칸과 세션 메모리에서 지웁니다. REST API
연결에서는 해당 입력칸과 버튼을 비활성화하고 `REST 불필요`로 표시합니다.
화면의 계좌번호는
코드에 고정한 값이 아니라 `GetLoginInfo("ACCNO")`가 반환한 원본 계좌의 기본
8자리를 `4자리-4자리`로 표시합니다.

프로그램 시작 시 Windows DPI 인식을 먼저 적용하고, `CommConnect()`가 성공하면
같은 프로세스에서 생성된 키움 OpenAPI+ 로그인 창만 찾아 화면 앞으로 표시합니다.
창 탐색은 백그라운드에서 수행하므로 앱 화면이나 COM 이벤트 처리를 멈추지 않으며,
상태 표시줄에는 `CommConnect` 반환코드와 로그인 창 탐색 결과가 표시됩니다.

로그인과 계좌 정보 수신이 완료되면 메인 `멀티주기 DMI 차트` 탭에서 초·분·시간
단위를 선택할 수 있습니다. 1·3·5·10·15·30·45분과 1시간은 키움
`opt10080`/`ka10080`의 공식 분봉 간격을 사용합니다. REST 연결의 1·5·10초봉은
공식 `ka10079` 1틱 이력을 먼저 실제 체결시간별 OHLC로 집계하고, 이후 WebSocket
주식체결 `0B`의 현재가와 체결량을 같은 차트에 이어 붙입니다. OpenAPI+ 연결은
실시간 주식체결을 수신한 시점부터 초봉을 생성합니다.

차트는 양봉·음봉, MA5·MA20, 우측 가격축, DMI/ADX 하단창, 강약 배경,
매수·매도 전환 표식, 봉 범위 확대·축소와 마우스 십자선 OHLC 툴팁을 제공합니다.
표시 주기를 바꿔도 자동매매 판단과 주문은 키움 일봉 DMI에 고정되어
있습니다. `DMI 차트 확대`는 현재 선택한 주기를 별도 창으로 엽니다.

## 관심종목

상단 `관심종목` 버튼에서 6자리 종목코드를 최대 20개까지 등록·삭제할 수 있으며,
등록 목록은 SQLite에 저장되어 프로그램을 다시 실행해도 유지됩니다. REST API로
연결하면 키움 공식 예제의 관심종목정보 요청 `ka10095`에 종목코드를 `|`로 묶어
한 번에 조회합니다. OpenAPI+ 연결에서는 동일 화면을 사용할 수 있도록 기존
현재가 TR을 호출 제한에 맞춰 순차 조회합니다.

목록에는 시장, 종목코드, 종목명, 현재가, 전일대비, 등락률, 거래량을 표시하고,
선택 종목 정보에는 거래대금, 시가·고가·저가, 매도·매수호가와 체결시간까지
표시합니다. 상승은 빨간색, 하락은 파란색으로 구분합니다. API 연결 전에도 종목을
미리 등록할 수 있으며, 연결 후 `새로고침`을 누르면 실제 시세를 채웁니다.

`선택 시 차트 자동 연결`이 켜진 상태에서 행을 선택하거나 `선택 연결`을 누르면
해당 종목을 메인 종목으로 바꾸고 현재가, 선택한 초·분·시간 차트와 실시간 체결을
연결합니다. 자동매매 서비스가 시작된 뒤에는 같은 선택 종목의 일봉 DMI가
전략 판단과 모의주문에 사용됩니다. 관심종목 선택 자체는 주문을 실행하지 않습니다.

## 키움 REST API 연결

`REST API 연결` 버튼에서는 `실전투자`와 `모의투자`를 선택합니다.
각 환경에 맞는 AppKey와 SecretKey로 `au10001` 접근토큰을 발급하고,
`ka00001`에서 계좌번호가 확인된 경우에만 녹색 `ON REST API 연결됨`으로
전환합니다. 브라우저 로그인 여부를 추측하지 않으며, 실제 키움 API의 토큰과
계좌 응답만 연결 근거로 사용합니다.

AppKey, SecretKey, 접근토큰은 설정 파일·SQLite·로그에 저장하지 않습니다.
연결 입력 창에서 한 번 사용하고 메모리 세션에만 유지하며, 토큰이 만료되거나
연결 검증이 실패하면 조회·전략·주문 기능을 차단합니다. AppKey와 SecretKey는
채팅, 화면 캡처, 소스코드 또는 Git 저장소에 올리지 마세요.

키움 공식 Python CLI는 Windows 자격 증명 관리자를 이용한 키 보관을 권장합니다.
이 통합 EXE는 OpenAPI+ 32비트 호환성을 유지하기 위해 공식 CLI를 내장하지 않고,
키 파일을 실행할 때만 읽은 뒤 별도로 저장하지 않는 방식으로 운용합니다.

공식 포털에서 AppKey와 App Secret은 1회만 다운로드할 수 있습니다. 연결 창의
`REST API 연결`을 열면 사용자 다운로드 폴더에서 같은 접두어를 가진 최신
`*_appkey.txt`와 `*_secretkey.txt` 또는 `*_appsecret.txt` 쌍을 자동으로 찾아
마스킹된 입력란에 불러옵니다. 버튼을 누르면 다시 검색합니다. 파일 경로와 키
내용은 저장하거나 로그에 남기지 않으며, 해당 파일명은 Git 추적에서도 제외됩니다.
접근토큰은 24시간 유효하므로 만료 후에는 같은 키 파일로 다시 연결해야 합니다.

실전투자 AppKey 발급과 API 인증에는 키움 포털의 IP 등록이 필요합니다. 오류
`8010`이 발생하면 등록된 IP와 현재 공인 IP가 같은지 확인하세요. 실전/모의 키를
서로 다른 서버에 사용해 `8030` 또는 `8031`이 발생하면 연결 환경을 바꾸거나 해당
환경의 키 파일을 다시 선택해야 합니다. IP 주소와 계좌번호는 프로그램에
하드코딩하지 않습니다.

등록된 실전투자 키와 허용 IP 환경에서 접근토큰, 계좌번호, 현재가, 3분봉,
계좌평가잔고 및 WebSocket 로그인까지 읽기 전용 통합 검증을 완료했습니다. 검증
과정에서는 주문 API를 호출하지 않았으며 계좌정보는 마스킹해서만 확인했습니다.

연결 후 다음 공식 REST 기능을 기존 화면과 전략 엔진에 연결합니다.

- 종목명·현재가: `ka10001` / `/api/dostk/stkinfo`
- 1~60분봉: `ka10080` / `/api/dostk/chart`
- 예수금·주문가능·출금가능금액: `kt00001` / `/api/dostk/acnt`
- 계좌평가잔고: `kt00018` / `/api/dostk/acnt`
- 실시간 체결: WebSocket `LOGIN` 후 `REG`, 국내주식 `0B`
- 장 운영 상태: WebSocket `0s`의 FID `215`와 `0B`의 장구분 FID `290`
- 모의 시장가 주문: 매수 `kt10000`, 매도 `kt10001` / `/api/dostk/ordr`
- 실전 시장가 주문: 매수 `kt10000`, 매도 `kt10001` / `/api/dostk/ordr`

실전 연결 후에도 `실거래 세션 승인(위험)`은 꺼진 상태입니다. 종목 세팅, 계좌와
잔고, 1주 이상 주문 수량, 고정 운용금액을 모두 확인한 뒤 체크하면 계좌·종목·수량·
운용금액을 다시 보여주는 확인창이 열립니다. 승인 값은 메모리에만 유지되며 앱 종료,
자동운용 중지, 연결 해제 또는 긴급 정지 때 즉시 사라집니다.

장 시작 전에 `자동 운용 시작`을 누르면 주문하지 않고 대기합니다. 키움 공식
장시작시간 `0s`의 FID `215=3` 또는 주식체결 `0B`의 FID `290=2`가 확인된 뒤에만
일봉 DMI 전략과 DMI·퍼센트 결합 조건을 평가하고 선택 수량으로 주문합니다. 장중에 프로그램을
늦게 실행해 `0s` 시작 이벤트가 지나간 경우에도 최근 `0B` 체결의 장구분으로 장중임을
확인합니다. `0B` 근거는 최근 30초 이내 체결만 인정하며, 장중 신호가 없거나
WebSocket이 끊기면 REST 클라이언트도 실주문을 거부합니다. 자동운용 시작 자체가
무조건 매수를 뜻하지 않으며 DMI 약세→강세 전환이 있어야 매수합니다.

REST WebSocket의 `REG` 성공 직후에는 `실시간 등록 완료·다음 체결 대기`를 표시합니다.
등록 종목에 새 거래가 발생해 첫 `0B`가 수신되면 현재가와 FID `290` 장구분을 시스템
로그에 한 번 기록하고, 장중 값 `2`이면 `정규장 장중(실시간 체결 확인)`으로 바뀝니다.
거래가 뜸한 종목은 등록 성공 뒤 첫 체결까지 수십 초 이상 걸릴 수 있습니다.

주문수량은 프로그램 시작 시 `0주`입니다. 편집 가능한 글자 칸 없이 별도
`주문 수량` 구획에 `0주 | - | +`만 표시하며 두 버튼으로 수량을 조절해야
매수·매도·전략 주문 버튼이 활성화됩니다. 0주는 API에 전송하지 않으며 자동으로
1주로 바꾸지도 않습니다. 수동 주문과 DMI 전략 주문 모두 선택한
수량을 키움 공식 매수 `kt10000`·매도 `kt10001`의 `ord_qty`에 그대로 전달합니다.
선택 수량이 운용 한도 또는 조회된 보유 수량을 넘으면 주문을 줄이지 않고 차단하여
사용자가 선택하지 않은 수량으로 주문되는 것을 막습니다.
매수는 기존 보유 수량을 포함한 현재가 기준 총 수량을 계산하며, 종목별 운용 한도와
계좌 주문가능금액 안에서는 같은 종목의 추가 매수를 허용합니다.

## 고정 운용금액과 DMI 상승 매수·하락 매도 주문

먼저 6자리 종목번호를 입력하고 `종목 세팅`을 눌러 회사명을 확인한 다음
`계좌잔고 불러오기`와 `현재가 불러오기`를 실행합니다. `금액 세팅`은 입력한
종목별 운용 한도금액이 키움 `kt00001`/`opw00001`의 주문가능금액보다 작고,
키움 `ka10001`/`opt10001` 현재가 1주 이상인 경우에만 허용됩니다.

세팅 시점의 운용 한도금액, 실제 현재가와 설정일을 종목별 SQLite에 저장합니다.
화면에는 설정일과 고정 기준가가 표시되고 운용금액 입력란은 잠깁니다. 프로그램을
종료하거나 실시간 주가가 오르내려도 이 값은 바뀌지 않으며 `리세팅`을 눌러야
삭제됩니다. 리세팅하면 자동운용을 중지하고 남은 상승·하락 조건도 함께 해제합니다.
`모의 현재가(테스트용)` 입력은 제거했으며 자동운용은 키움 실제 조회·실시간
현재가만 사용합니다.

왼쪽 `오를때 DMI 자동 매수`는 일봉 DMI가 강세이면서 고정 기준가보다 입력
비율만큼 상승한 `+%` 목표가에 도달할 때 자동매수합니다. 오른쪽 `내릴때 DMI 자동
매도`는 일봉 DMI가 약세이면서 입력 비율만큼 하락한 `-%` 목표가에 도달할 때
자동매도합니다. 예를 들어 기준가 10,000원에서 0.2% 매수 목표는 10,020원,
0.2% 매도 목표는 9,980원이며 해당 DMI 방향까지 동시에 맞아야 주문합니다.

퍼센트 칸에 `0.2`를 입력한 것만으로는 주문 조건이 활성화되지 않습니다. 화면에
`0.2% 입력됨 · 설정 버튼 필요`가 표시되며, `DMI 매도 설정` 또는 `DMI 매수 설정`
버튼을 눌러 확인창을 통과하면 `실주문 대기`와 목표가·수량·인증 방식이 표시됩니다.
입력값을 다시 수정하면 기존 설정은 즉시 해제되므로 설정 버튼을 다시 눌러야 합니다.

상승 매수와 하락 매도는 서로 독립적인 일회성 조건입니다. 상승 목표에 도달해
매수하면 상승 매수 설정만 지워지고, 하락 목표에 도달해 매도하면 하락 매도 설정만
지워집니다. 반대편 조건은 사용자가 별도로 실행하거나 수정할 때까지 유지됩니다.

목표가와 필요한 DMI 강약을 동시에 만족하면 기존 키움 공식 시장가 주문 경로로 정확히 1회만 요청하며,
성공 여부와 관계없이 해당 퍼센트 조건은 즉시 지웁니다. 설정 시 선택한 계좌를
조건에 함께 고정하고 실행 시 현재 선택 계좌와 다시 대조합니다. OpenAPI+는 화면의
`비밀번호 세팅`으로 확인된 4~8자리 값을 주문 직전 `opw00001`/`opw00018` 잔고
재조회에 사용합니다. REST API는 공식 규격대로 비밀번호가 아니라 접근토큰으로
계좌와 잔고를 재확인합니다. 비밀번호와 토큰은 조건이나 SQLite에 저장하지 않습니다.
고정 운용금액과 기준가는 리세팅 전까지 유지됩니다.

매수 요청 직전에도 선택 수량의 예상금액이 최근 조회된 계좌 주문가능금액을
넘는지 다시 검사합니다. 운용금액보다 주가가 높아져 1주도 살 수 없거나 주문가능
금액이 부족하면 주문을 전송하지 않습니다.

실계좌에서는 `실거래 세션 승인(위험)`을 켜고 설정 시 별도 최종 확인까지 통과해야
합니다. 조건 도달 시 키움 `0s`의 KRX 장중 값 `3` 또는 최근 `0B`의 장중 값 `290=2`,
계좌, 비밀번호 확인 상태와 실거래 세션 승인을 다시 검사한 뒤 추가 확인 없이 1회
주문합니다. 평일이라도 휴장일 또는 장중 신호 미수신 상태에서는 주문하지 않으므로
먼저 모의투자에서 충분히 검증해야 합니다.

REST 실시간 수신은 별도 백그라운드 연결에서 동작합니다. 키움 서버의 일반 문자열
또는 JSON `PING`을 형태 그대로 응답하고 `REAL` 메시지의 현재가(10),
등락률(12), 누적거래량(13), 체결량(15), 체결시간(20), 장구분(290)을 처리합니다.
초봉 거래량은 누적거래량(13)이 아니라
체결량(15)을 합산합니다. 거래가 없는 초 구간을 임의 가격으로 채우지 않으며,
장 마감 뒤에는 `ka10079` 이력이 표시되고 새 `0B` 봉은 다음 장중 체결부터
추가됩니다. 현재 UI는 한 번에 한 종목을 등록하며, 종목을 바꾼 뒤
`실시간 시세 시작`을 다시 누르면 새 종목으로 교체됩니다.

키움 API는 영웅문 화면의 DMI 값이나 분홍/파랑 배경색을 직접 제공하지 않습니다.
이 버전은 공식 `ka10081`/`opt10081` 일봉의 고가·저가·종가로 1~99일 Wilder DMI를
직접 계산합니다. `-DI` 우세에서 `+DI` 우세로 바뀌는 모든 새 일봉은 매수, 반대 전환은
매도로 판단하며 같은 일자의 봉은 한 번만 판단해 중복 주문을 막습니다. API의
수정주가, 미완성 봉, 반올림 방식에 따라 영웅문 표시값과 소수점 차이가 날 수
있으므로 실전 사용 전 모의투자에서 충분히 비교해야 합니다.

공식 페이지:

- https://openapi.kiwoom.com/intro?dummyVal=0
- https://openapi.kiwoom.com/mgmt/VOpenApiRegView?dummyVal=0
- https://openapi.kiwoom.com/guide/index?dummyVal=0
- https://openapi.kiwoom.com/guide/apiguide?dummyVal=0
- https://github.com/Kiwoom-Securities/Kiwoom-REST-API

REST API는 OpenAPI+ ActiveX와 달리 32비트 모듈 설치가 필요하지 않지만, 이
프로젝트의 32비트 EXE에서도 함께 사용할 수 있습니다. 키움 홈페이지 브라우저
로그인, OpenAPI+ 로그인, REST 접근토큰은 서로 다른 연결입니다. 홈페이지에
로그인되어 있다는 이유만으로 앱의 ON 표시가 켜지지는 않습니다.

REST API는 계좌 비밀번호를 전송하지 않습니다. 접근토큰 발급 후 공식
`ka00001`에서 받은 계좌번호와 현재 선택 계좌가 일치할 때만 `kt00001`과
`kt00018`을 호출하고, 계좌정보 창에 예수금·주문가능금액·출금가능금액·D+2
추정예수금과 평가잔고를 함께 표시합니다.
키움 공식 GitHub의 `kt10000` 매수·`kt10001` 매도 예제도 요청 헤더의 Bearer
접근토큰과 종목·수량·거래구분만 사용하며 계좌 비밀번호 요청 항목은 없습니다.
따라서 REST 연결에서는 비밀번호칸을 주문 데이터에 섞지 않습니다.

OpenAPI+ 필요 조건:

- Windows PC
- 키움 OpenAPI+ 설치
- pywin32 설치
- 32비트 실행 파일
- 키움 OpenAPI+ 서비스 사용 등록
- HTS ID 및 공동인증서 준비

키움 OpenAPI+가 설치되어 있지 않거나 비트 수가 맞지 않으면 앱은 한글 오류
메시지를 보여주고 실거래 기능은 실행하지 않습니다.

서비스 신청 화면에 `등록`이 표시되어도 PC에 OpenAPI+ 모듈이 별도로 설치되어
있어야 합니다. 키움 공식 홈페이지에서 OpenAPI+ 설치파일을 받은 뒤 설치하고,
`KiwoomAutoTrader-32bit.exe`를 다시 실행해 주세요. 로그인 창에서는 처음에는
반드시 `모의투자 접속`을 선택해 충분히 검증하는 것을 권장합니다.

## 키움 연결용 32비트 EXE 빌드

키움 OpenAPI+는 32비트 ActiveX이므로 계좌 연결 버튼을 사용하려면 32비트 EXE를
실행해야 합니다.

```bat
scripts\build_windows_exe_32bit.bat
```

실행 파일 생성 위치:

```text
dist\KiwoomAutoTrader-32bit.exe
```

## 로컬 실행

```bat
python -m kiwoom_auto_trader.main
```

## 로컬 EXE 빌드

```bat
scripts\build_windows_exe.bat
```

실행 파일 생성 위치:

```text
dist\KiwoomAutoTrader.exe
```

## GitHub Actions

저장소를 GitHub에 푸시한 뒤 Actions 탭에서 `Build Windows EXE` 워크플로를
실행하면 `KiwoomAutoTrader-windows-exe` 아티팩트가 생성됩니다.

## 실거래 주의

실계좌 주문 경로는 구현되어 있지만 기본 잠금 상태입니다. 실제 주문 전에는 반드시
모의투자에서 동일 종목·수량·DMI 설정으로 반복 검증하고, 고정 운용금액과 계좌
주문가능금액을 확인하세요. 개발·자동 테스트에서는 실계좌 주문을 전송하지 않습니다.

## 아직 검증이 필요한 부분

- 키움 OpenAPI+가 설치된 실제 32비트 Windows 환경에서 TR 응답 확인
- REST 모의투자 AppKey로 토큰·계좌·WebSocket·모의주문 종합 확인
- REST 실전 계좌에서 장중 신호·주문 접수·체결·거부 응답을 소액으로 수동 검증
- 영웅문 DMI 표시값과 장중 장시간 비교 검증
- 쾌속주문 툴 직접 연동
- 장중 장시간 운용 테스트
- 실계좌 주문 전 모의투자 계좌 반복 검증
